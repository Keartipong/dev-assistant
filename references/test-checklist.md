## 1. กฎตรวจ Input 3 ส่วน
- **องค์ประกอบ:** (1) Requirement (2) โค้ด (3) เทสที่มีอยู่
- **กรณีไม่มี Requirement:** แจ้งทันทีว่า *"ตรวจได้เฉพาะโค้ดกับเทส และไม่สามารถบอกได้ว่าขาดฟีเจอร์หรือไม่"*
- **กรณี Requirement ไม่ชัดหรือขัดกับโค้ด:** แจ้งจุดที่ขัดกันทันที ห้ามเดาสเปกเอง

## 2. มิติตรวจ 4 ด้าน
1. **Req ที่ยังไม่มีเทส (Untested Req):** ข้อกำหนดใน Req ที่ยังไม่มี test case รองรับทั้ง happy path และ failure path
2. **โค้ดที่เทสไม่ถึง (Uncovered Code):** branch `if/else/switch`, ternary `? :`, early return, บล็อก `catch/error path` ที่เทสยังไม่ครอบคลุม
3. **Edge Case ที่ขาด (Missing Edge Cases):** ค่าขอบเขตและกรณีผิดปกติตามหมวดที่ 3 ที่ยังไม่มีในเทสหรือโค้ดไม่ดัก
4. **จุดที่ Req กับโค้ดไม่ตรงกัน (Req-Code Mismatch):** เงื่อนไขตรรกะ (`<` vs `<=`), สิทธิ์ role, สูตรคำนวณ, status code หรือ response ไม่ตรง Req

## 3. รายการ Edge Cases
- **ค่าว่างและชนิดข้อมูล:** `null`, `undefined`, `""`, `"   "` (ช่องว่างล้วน), `[]`, `{}`, ชนิดข้อมูลผิดประเภท (`NaN`)
- **ตัวเลขและขอบเขต (Boundary):** `0`, ค่าติดลบ (`-1`), ทศนิยม, ค่าขอบเขตพอดี (`N-1`, `N`, `N+1`), ค่าเกินเพดานสูงสุด (`MAX_SAFE_INTEGER`)
- **ข้อความและวันที่:** อักขระพิเศษ/อิโมจิ/SQL-HTML payload, ความยาวเกินกำหนด, วันที่สิ้นเดือน/ปีอธิกสุรทิน, เขตเวลา (Timezone), พ.ศ. vs ค.ศ.
- **ระบบและพฤติกรรมผู้ใช้:** กดซ้ำรัวๆ (double submit), ข้อมูลซ้ำ (duplicate), สิทธิ์ไม่ตรง role (401/403), ไม่มีข้อมูล (404), API ล่ม/timeout (500/504)
